# Objective
Continue slimming `routes/main_routes.py` by extracting only the contiguous analytics, dashboard, reports, and automations API block into one dedicated routes module, with route-focused validation to preserve current registration and middleware behavior.

# Context
- .planning/STATE.md
- routes/main_routes.py
- routes/admin_user_routes.py
- routes/page_routes.py
- routes/sales_routes.py
- routes/workspace_routes.py
- tests/contracts/test_contract_routes.py
- tests/parity/test_endpoint_middleware_parity.py

# Scope
In scope:
- GET /api/admin/analytics/data
- POST /api/admin/analytics/clear_cache
- GET /api/dashboard/stats
- GET /api/reports/stats
- GET and POST /api/reports/scheduled
- DELETE /api/reports/scheduled/<int:report_id>
- GET and POST /api/automations
- PUT and DELETE /api/automations/<int:automation_id>

Out of scope:
- All /api/admin/subscription* routes, including /api/admin/subscriptions
- The duplicated /api/customers* routes
- The duplicated /api/products* routes
- Any unrelated route cleanup or behavior changes

# Constraints
- Preserve the existing extraction pattern: dedicated routes module, `import app as app_module`, copy globals from `app_module`, and expose `register_*_routes(app)`.
- Keep the extracted block in a single new module for this step; do not split it across multiple new files.
- Update `routes/main_routes.py` only enough to import and call the new `register_*_routes(app)` alongside the existing route modules.
- Do not make a git commit for this quick task.

- routes/analytics_routes.py or an equivalent single dedicated module name

- Preserve current handlers, decorators, helper usage, and response shapes.
